🔄 Angular 19 HTTP Interceptors Full Tutorial

HTTP Interceptors in Angular are powerful tools that allow us to inspect, transform, or log HTTP requests and responses globally. They are ideal for:

  • Adding authentication tokens
  • Logging requests and responses
  • Handling errors globally

💡 What is an HTTP Interceptor?

An HTTP Interceptor is a class that implements HttpInterceptor. It runs before and after every HTTP request made by Angular's HttpClient. 

      
        export interface HttpInterceptor {
          intercept(req: HttpRequest<any>, next: HttpHandler): Observable<HttpEvent<any>>;
        }

🧱 Creating an Interceptor in Angular 19

1. Token Interceptor Example

      
    import { Injectable } from '@angular/core';

    import { HttpInterceptor, HttpRequest, HttpHandler, HttpEvent } from '@angular/common/http';

    import { Observable } from 'rxjs';

    @Injectable()
    export class TokenInterceptor implements HttpInterceptor {
      intercept(req: HttpRequest<any>, next: HttpHandler): Observable<HttpEvent<any>> {
      const token = localStorage.getItem('token');

    if (token) {
      const cloned = req.clone({
      headers: req.headers.set('Authorization', `Bearer ${token}`)
      });
      return next.handle(cloned);
    }

      return next.handle(req);
      }
    }

2. Error Handling Interceptor

      
        import { Injectable } from '@angular/core';

        import { HttpInterceptor, HttpRequest, HttpHandler, HttpErrorResponse } from '@angular/common/http';

        import { Observable, catchError, throwError } from 'rxjs';

        @Injectable()
        export class ErrorInterceptor implements HttpInterceptor {
          intercept(req: HttpRequest<any>, next: HttpHandler): Observable<any> {
          return next.handle(req).pipe(
          catchError((error: HttpErrorResponse) => {
            alert(`Error: ${error.status} - ${error.message}`);
            return throwError(() => error);
          })
          );
          }
        }

⚙️ Providing Interceptors in Angular 19

Angular 15+ supports functional providers with withInterceptors().

main.ts:

      
    import { bootstrapApplication } from '@angular/platform-browser';

    import { AppComponent } from './app/app.component';

    import { provideHttpClient, withInterceptors } from '@angular/common/http';

    import { TokenInterceptor } from './app/interceptors/token.interceptor';

    import { ErrorInterceptor } from './app/interceptors/error.interceptor';

    bootstrapApplication(AppComponent, {
    providers: [
      provideHttpClient(
        withInterceptors([
          TokenInterceptor,
          ErrorInterceptor
        ])
      )
    ]
    });

📋 Interceptor Order Matters

If you use multiple interceptors, they're called in the order you register them. Responses flow back in reverse.

// Request: TokenInterceptor → ErrorInterceptor → HTTP call // Response: HTTP call → ErrorInterceptor → TokenInterceptor

📌 Interceptor Use Cases

  • Authentication: Add Authorization headers (JWT)
  • Error Handling: Catch 401, 500 responses globally
  • Loading Spinner: Start spinner on request, stop on response
  • Logging: Log all outgoing/incoming traffic

✅ Summary

  • Interceptors sit between your app and the server
  • They can modify requests, responses, or errors
  • Register interceptors using provideHttpClient(withInterceptors([]))
  • Great for tokens, global errors, analytics

📦 Bonus: Full Token Interceptor with Expiry Check

      
    intercept(req: HttpRequest<any>, next: HttpHandler): Observable<HttpEvent<any>> {
    const token = localStorage.getItem('token');
    const isExpired = false; // use JWT decode lib to check expiry

    if (token && !isExpired) {
      const cloned = req.clone({
      headers: req.headers.set('Authorization', 'Bearer ' + token)
      });
      return next.handle(cloned);
      }

      return next.handle(req);
    }
✅ You can use libraries like jwt-decode to decode and verify token expiry before sending.
