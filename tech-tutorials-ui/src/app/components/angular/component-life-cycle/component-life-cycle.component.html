Angular Component Lifecycle Hooks

1. ngOnChanges(changes: SimpleChanges)

When: Called when any @Input() property changes.

Use: To react to data passed in from a parent component.

Note: Called before ngOnInit, and on every change.

2. ngOnInit()

When: Called once after the first ngOnChanges.

Use: Initialization logic, API calls, subscriptions.

Note: Runs only once per component lifecycle.

3. ngDoCheck()

When: Called during every change detection cycle.

Use: For custom change detection logic.

Note: Be cautious — it can affect performance.

4. ngAfterContentInit()

When: After external content is projected via <ng-content>.

Use: When you need to act on projected content.

Note: Called once.

5. ngAfterContentChecked()

When: After every check of projected content.

Use: Monitor changes in projected content.

6. ngAfterViewInit()

When: After the component's view (and child views) are initialized.

Use: DOM operations, working with @ViewChild.

Note: Called once.

7. ngAfterViewChecked()

When: After every check of the component’s view and its children.

Use: To track view updates Angular doesn't detect automatically.

8. ngOnDestroy()

When: Just before Angular destroys the component.

Use: Cleanup — unsubscribe from observables, stop timers, etc.

Note: Crucial to prevent memory leaks.

🔁 Lifecycle Summary Table

Hook Called When? Typical Use
ngOnChanges On @Input() property changes React to external input
ngOnInit After first ngOnChanges Initialize logic, load data
ngDoCheck Each change detection cycle Custom change detection
ngAfterContentInit After content projection Act on projected content
ngAfterContentChecked Every content check Watch content changes
ngAfterViewInit After view is initialized DOM access, ViewChild
ngAfterViewChecked Every view check Track view updates
ngOnDestroy Before component is removed Unsubscribe, cleanup
